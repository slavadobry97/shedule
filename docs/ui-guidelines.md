# UI-гайдлайны проекта

Ориентир — Apple Human Interface Guidelines: сдержанность, материалы, «живая»
инерция, читаемость. Не копия iOS, а набор конкретных правил для этого
приложения. Правила обязательны к соблюдению в новом коде.

## 1. Материалы и размытие

Рецепт «стекла» от Apple: насыщенность 180% + размытие 20px, подложка 80%.

```tsx
<header className="sticky top-0 z-50 border-b bg-background supports-[backdrop-filter]:bg-background/80 backdrop-blur-[20px] backdrop-saturate-180">
```

Правила:
- Материал используется для **плавающих слоёв**: шапка, панели поверх контента.
  Обычные поверхности (карточки, таблицы) — плотные, без размытия.
- Фон под материалом — всегда `bg-background` (в тёмной теме это не чёрный, а
  `hsl(222 84% 9.5%)`), чтобы стекло не выглядело грязным.
- Без поддержки `backdrop-filter` фон должен быть непрозрачным — поэтому
  базовый класс `bg-background`, а прозрачность включается через
  `supports-[backdrop-filter]:`.
- Фильтры составляются **отдельными утилитами Tailwind**:
  `backdrop-blur-[20px] backdrop-saturate-180` → `backdrop-filter: blur(20px) saturate(180%)`.
  Собирать их в один arbitrary-значение нельзя:
  `backdrop-blur-[saturate(180%)_blur(20px)]` даёт вложенный
  `blur(saturate(180%) blur(20px))` — невалидный фильтр.

## 2. Движение

- Длительность: **0.2–0.35 с** для переходов внутри экрана, до 0.5 с для
  появления панелей. Никаких «резиновых» анимаций.
- Кривая: `cubic-bezier(0.22, 1, 0.36, 1)` — мягкое торможение без отскока.
  Прописывается в `@theme` или в `transition` классами Tailwind.
- Появление содержимого при прокрутке: `y: 12–16px` + `opacity`, со сдвигом
  по времени (stagger) — не «всё сразу».
- `prefers-reduced-motion` — **обязателен**: любая анимация проверяет
  `useReducedMotion()` (framer-motion) и отключается. В `globals.css` для
  CSS-анимаций — `@media (prefers-reduced-motion: reduce)`.
- Анимация не должна блокировать ввод: `pointer-events-none` на декоративных
  слоях.

### Как это сделано

Кривая и длительность по умолчанию — в теме, поэтому все `transition-*`
утилиты в приложении уже используют их:

```css
/* app/globals.css */
@theme {
  --default-transition-duration: 250ms;
  --default-transition-timing-function: cubic-bezier(0.22, 1, 0.36, 1);
  --ease-smooth: cubic-bezier(0.22, 1, 0.36, 1);
}
```

Для framer-motion — общий хелпер `lib/motion.ts`:

```tsx
import { useReducedMotion } from "framer-motion";
import { MOTION_DURATION, motionTransition } from "@/lib/motion";

const reduceMotion = useReducedMotion();

<motion.div transition={motionTransition(reduceMotion, { duration: MOTION_DURATION.fast })} />
```

`motionTransition` при включённом reduced motion возвращает `{ duration: 0 }` —
анимация схлопывается, элемент появляется сразу. Свои `transition={{ duration }}`
в компонентах не пишем: только через хелпер.

Длительности: `MOTION_DURATION.fast` (0.2) — наведение и появление;
`base` (0.25) — переходы внутри экрана; `panel` (0.4) и `slow` (0.5) — панели.
Пружина `MOTION_SPRING` — только для жестов и свайпов, без отскока.

CSS-анимации (в том числе `animate-in` из `tw-animate-css`) отключаются
глобально в `globals.css` через `@media (prefers-reduced-motion: reduce)`.

## 3. Цели касания

- Минимум **44×44 px** для любой интерактивной цели (HIG). На плотных
  десктопных тулбарах допускаются 32×32, но не меньше.
- Между соседними целями — зазор от 8 px, иначе промахи мимо.
- Иконка-кнопка: `size-9`/`size-10` (36/40) в шапке, `size-11` (44) в
  мобильном интерфейсе.
- Состояние `pressed` — через `active:scale-[0.98]`, не через смену цвета:
  тактильность важнее контраста.

## 4. Типографика

- Шрифты проекта: **Evolventa** (дисплейный/заголовки) и **Geist Mono**
  (числа, метки, код). Системный sans — основной текст.
- Шкала: 11 / 13 / 14 / 15 / 17 / 22 / 28 / 36 / 48. Шаг — примерно 1.2.
- Заголовки: `tracking-[-0.01em]`…`[-0.02em]`, без `uppercase` (кроме
  микро-подписей вроде «СИСТЕМНАЯ ОШИБКА»).
- Микро-подписи (`text-[10px]`, `text-[11px]`) — только для служебных
  метаданных, всегда с `tracking-[0.16em]`/`[0.2em]` и `uppercase`.
- Числа в таблицах — `tabular-nums`, чтобы колонки не «прыгали».

## 5. Тёмная тема

- Тема следует системе (`next-themes`, `defaultTheme="system"`).
- Фон — не чистый чёрный: тёмная тема на токенах, контраст текста не ниже
  чем в светлой.
- Цвет — только токены (`bg-primary`, `text-muted-foreground`, `border-border`).
  Сырых `#hex` в разметке быть не должно.
- Цвет не должен быть единственным носителем смысла: статус всегда
  сопровождается текстом или иконкой.

## 6. Поверхности: canvas и background

Два разных фона, не путать:

| Токен | Что это | Где применяется |
|-------|---------|-----------------|
| `--canvas` | Полотно страницы — фон, на котором лежат все поверхности | `body`, экраны загрузки/ошибки/приветствия, стеклянная шапка |
| `--background` | Поверхность: карточка, панель, поповер, шторка, кнопка | `components/ui/*`, карточки расписания |

`--canvas` — тонированный: 4% бренда, подмешанные в белый (светлая тема)
или в почти-чёрный (тёмная). Карточки остаются чистыми и читаются как
приподнятые над полотном.

Имена:

- `canvas`, а не `bg` — «полотно» устоявшийся термин для подложки сцены
  (Shopify Polaris, Figma, Adobe). `bg` слишком общо и совпадает по смыслу
  с утилитами `bg-*`.
- `background` не переименовываем: в конвенции shadcn/Tailwind это уже
  «поверхность», и переименование сломало бы семантику карточек.
- Оба токена — семантические: в разметке только `bg-canvas` / `bg-background`,
  никаких `bg-slate-50`.

Значение canvas задано один раз через `light-dark()`: ветку темы выбирает
`color-scheme`, который `next-themes` ставит на `<html>`. Тон задаётся
`--brand-fixed` — фирменным синим, который не меняется от темы (`--brand`
в тёмной теме становится белым под текст). В `@theme inline` ссылаться на
сырой токен: переменные `@theme inline` в `:root` не попадают, поэтому
`var(--color-brand)` не разрешится.

## 7. Состояния и доступность

- Фокус всегда виден: `focus-visible:ring-*` (в `button.tsx` уже есть).
- `outline-none` в v4 заменён на `outline-hidden` (семантика «прозрачный, но
  сохраняющий»).
- Иконки без текста — `aria-hidden` либо `sr-only` подпись.
- Иконка-статус (ошибка, изменение) — цвет + форма + текст.

## 8. Haptics

- Вибрация только там, где она несёт смысл: свайп недели, смена вкладки,
  подтверждение действия. Не на каждое касание.
- `navigator.vibrate` и не на десктопе (media-agnostic, только мобильные).

### Как это сделано

Единый хелпер `lib/haptics.ts` — вызов безопасен в любом месте:

```tsx
import { haptic } from "@/lib/haptics";

haptic("light");   // короткий отклик
haptic("success"); // подтверждение: [10, 40, 12]
```

Внутри он проверяет: поддержку `navigator.vibrate`, что устройство сенсорное
(`pointer: coarse` или `maxTouchPoints > 0`) и что не включён
`prefers-reduced-motion`. Вне мобильных и при reduced motion вызов — no-op,
поэтому проверки в компонентах не нужны.

Где вызывается сейчас: свайп недели/дня в мобильном расписании, смена вкладки
«Календарь / Таблица», сохранение профиля («Моя группа» / преподаватель).

## 9. Безопасные зоны

- На устройствах с вырезом: `env(safe-area-inset-*)` для верхнего и нижнего
  отступов (`pt-[env(safe-area-inset-top)]`,
  `pb-[env(safe-area-inset-bottom,0px)]`).

## 10. Фирменная палитра

Брендбук обновлён 21.10.2026.

| Имя | Токен | Pantone | RGB | HEX | Где в системе |
|-----|--------|---------|-----|-----|---------------|
| Royal blue | `--royal-blue` | 286 C | 16 47 161 | `#102FA1` | `--brand`, `--primary`, `--ring` (светлая тема) |
| Navy blue | `--navy-blue` | 2758 C | 8 37 103 | `#082567` | градиенты бренда |
| Ruby | `--ruby` | 7627 C | 169 20 15 | `#A91917` | `--destructive` (светлая тема) |
| Ruby (наведение) | `--ruby-hover` | — | 122 14 11 | `#7A0E0B` | `--destructive-hover` (светлая тема) |
| — | — | 656 U | 213 37 103 | `#D5E4F4` | пока не в токенах |

Два слоя токенов:
- **Имена палитры** (`--royal-blue`, `--navy-blue`, `--ruby`) — источник правды
  для цветов, доступны и как утилиты: `bg-royal-blue`, `text-ruby`.
- **Семантические роли** (`--primary`, `--destructive`, `--brand`, `--ring`) —
  ссылаются на палитру. В разметке используются роли, а не имена: цвета
  меняются — роли остаются.

- Основной синий идёт и в бренд (логотип, текст), и в интерактив (кнопки,
  ссылки, фокус) — один синий во всём продукте.
- Фирменный градиент: `linear-gradient(135deg, var(--navy-blue), var(--royal-blue))`
  — токен `--brand-gradient`, утилита `bg-brand-gradient`. Заставка загрузки,
  брендовые блоки. Градиент не зависит от темы: это бренд, а не поверхность.
- Полотно страницы тонируется основным синим: `color-mix(in srgb, #102FA1 4%, …)`.
- Наведение на красную кнопку — отдельный токен `--destructive-hover` (`#7A0E0B`),
  а не прозрачность: 90% от `#A91917` давали не тот тон, что в брендбуке.
- Роли сообщений: **информация — фирменный синий** (`--info` → `--royal-blue`),
  **ошибка — брендовый красный** (`--destructive` → `--ruby`), внимание —
  янтарный (`--warning`). Красным помечают только настоящие ошибки: если
  подсказку покрасить в красный, она читается как сбой.
- В тёмной теме бренд-текст остаётся белым, а акцент и ошибка берут **светлый
  шаг того же тона**: `--primary: hsl(227 75% 55%)`, `--destructive: hsl(1 70% 55%)`.
  Тёмный Pantone на почти чёрном фоне нечитаем: `#102FA1` на `#020817` даёт
  1.75:1 — кнопка тонет в фоне.

- [ ] Цвета — только токены
- [ ] Фокус виден с клавиатуры
