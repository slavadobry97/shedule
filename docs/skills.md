## Тестирование и код

### tdd

- **Автор/источник:** [mattpocock/skills](https://www.skills.sh/mattpocock/skills/tdd)
- **Что делает:** ведёт цикл red → green → refactor так, чтобы тесты стоило
  сохранять. Ключевые правила: тестировать поведение через публичные интерфейсы,
  а не внутренности; один тест → одна порция реализации; тесты писать на
  «швах» — заранее согласованных границах наблюдаемого поведения; рефакторить
  только после зелёного прогона.
- **Когда полезен:** любой инкрементальный фичеворк, где хочется, чтобы тесты
  переживали рефакторинги и читались как спецификация.
- **Вердикт: ✅ взять.** У проекта идеальные «швы»: `lib/time-utils.ts`
  (`isLessonActive`), `lib/schedule-utils.ts` (склейка подгрупп),
  `lib/lesson-type-colors.ts`, парсинг в `utils/loadSchedule.ts` — именно тут
  живут баги классов «часовой пояс» и «12-часовой формат». Тестового раннера в
  проекте нет — первый шаг: vitest. Принципы скилла просты, ценность его —
  дисциплина цикла.

### improve-codebase-architecture

- **Автор/источник:** [mattpocock/skills](https://www.skills.sh/mattpocock/skills/improve-codebase-architecture)
- **Что делает:** ищет «мелкие» (shallow) модули и тесные связки, предлагает
  «углубляющие» рефакторинги по принципу Оустерхаута («маленький интерфейс
  прячет большую реализацию»). Генерирует несколько альтернативных дизайнов
  интерфейсов параллельными суб-агентами и оформляет RFC в GitHub Issues.
- **Когда полезен:** активно меняющиеся области кодовой базы с накопившейся
  связанностью.
- **Вердикт: ⚠️ идеи — да, процесс — нет.** Сама оптика («deep module», тест
  на удаляемость, интерфейс как тестовая поверхность) полезна; конвейер из
  параллельных суб-агентов и RFC-issues рассчитан на команду и GitHub Issues,
  которых у нас нет.

### setup-matt-pocock-skills

- **Автор/источник:** [mattpocock/skills](https://www.skills.sh/mattpocock/skills/setup-matt-pocock-skills)
- **Что делает:** разовый конфиг-скаффолд для suite Matt Pocock: определяет
  трекер задач (GitHub/GitLab/markdown/custom), словарь triage-меток и структуру
  доменных доков (GLOSSARY.md, ADR в `docs/agents/`), записывает конфиг в
  корневой файл репозитория.
- **Когда полезен:** один раз на репозиторий, до использования tdd/triage/
  to-issues и прочих его скиллов, если берётся весь конвейер.
- **Вердикт: ❌.** Предполагает GitHub Issues и ADR-процесс; у нас канбан на
  `mcp-kanban` (см. AGENTS.md) и соло-режим. Скилл tdd можно использовать и
  без этого конфига.

## Русский текст

### sasha

- **Автор/источник:** [mishanaer/deslop](https://github.com/mishanaer/deslop/tree/main/sasha), каталог `sasha`
- **Что делает:** пишет, правит и ревьюит русский текст в трёх контекстах —
  интерфейсы (кнопки, ошибки, тултипы, плейсхолдеры), маркетинг (лендинги,
  рассылки), документация (README, гайды). Правила: текст служит задаче
  пользователя (лучше починить интерфейс, чем объяснять его словами); тон
  нейтральный, без шуток и хайпа; ошибки — «что случилось → что делать → чего
  ждать»; не выдумывать поведение продукта; сохранять ключи локализации и
  интерполяцию (`{name}`, ICU). Отдельно умеет генерить UI-компоненты с текстом
  в 2–4 вариантах и возвращает структурированное ревью (критично / типографика /
  до-после).
- **Когда полезен:** любая правка пользовательских строк, сообщений об ошибках,
  справки и README.
- **Вердикт: ✅ взять для UI-текстов.** Весь интерфейс проекта на русском, и
  формулировки ошибок/тултипов — постоянное слабое место. Не применяется к
  обычным ответам и переписке — только к продукт-текстам.

### humanizer-ru

- **Автор/источник:** [ilyautov/humanizer-ru](https://github.com/ilyautov/humanizer-ru)
- **Что делает:** редактирует русский AI-текст, снимая следы генерации: 67
  паттернов в 16 категориях + 21 абсолютный запрет («В современном мире…»,
  «Стоит отметить…»). Локальная редактура вместо переписывания, факт-замок
  против искажения утверждений, сканер с баллом чистоты 0–100 и учётом жанра.
  Поставки: SKILL.md, Python-сканер (`ru-humanizer` на PyPI), CLI, MCP-сервер,
  GitHub Action.
- **Когда полезен:** чистка лендингов, changelog, статей, документации,
  написанных агентом.
- **Вердикт: ⚠️ точечно.** UI-строкам проекта лаконичность уже задана правилами
  AGENTS.md; реальная польза — для `PUBLIC_CHANGELOG.md`, `/landing` и README,
  где текста много и он генерируется агентом. Это инструмент редактуры, а не
  обход AI-детекторов (автор честно это заявляет).

## Мета-скиллы и инфраструктура

### grill-me

- **Автор/источник:** [mattpocock/skills](https://www.skills.sh/mattpocock/skills/grill-me)
- **Что делает:** превращает агента в дотошного интервьюера: вскрывает план по
  веткам решений вопрос за вопросом, самостоятельно отвечает на часть вопросов
  по кодовой базе, доводит до общего понимания до начала реализации.
- **Когда полезен:** дизайн-ревью, проверка архитектуры, планирование крупных
  работ.
- **Вердикт: ⚠️ на крупные решения.** Для повседневных задач оверхед (каждая
  карточка и так проходит ревью человека), но перед редизайном навигации или
  сменой источника данных — полезный фильтр дыр в плане.

### find-skills

- **Автор/источник:** [vercel-labs/skills](https://www.skills.sh/vercel-labs/skills/find-skills)
- **Что делает:** мета-скилл поиска и установки других скиллов: `npx skills
  find [query]`, `npx skills add <package>`; рекомендует выбирать по сигналам
  качества (1k+ установок, официальные авторы, звёзды).
- **Когда полезен:** «найди скилл для X» в начале новой задачи.
- **Вердикт: ⚠️ утилита.** Проекту ничего не даёт напрямую; держать в уме как
  способ поиска, ставить ради галочки незачем.

### ECC

- **Автор/источник:** [affaan-m/ECC](https://github.com/affaan-m/ECC) (MIT)
- **Что делает:** тяжёлый «harness» для агентов: workflow plan → test →
  implement → review → verify → remember; 71 специализированный суб-агент,
  311 скиллов, 97 slash-команд, детерминированные hooks (блокировка секретов,
  батчи форматирования), Memory Vault (переносимая память между сессиями),
  AgentShield (скан безопасности конфигов). Установка через `npx
  ecc-universal setup` или plugin marketplace Claude Code.
- **Когда полезен:** командная разработка на Claude Code с полным конвейером
  дисциплины; проект с богатой инфраструктурой ревью.
- **Вердикт: ❌ избыточен.** Устанавливает параллельную систему управления
  работой, которая продублирует и размоет наш AGENTS.md + канбан-процесс;
  Memory Vault и хуки интересны как идеи, но не как зависимость соло-проекта.
  Принцип «Optimize the context window. Persist everything else» — хорошая
  мантра, воплощать стоит точечно (наш аналог — файл памяти и карточки доски).

## Итог

Практическая программа минимум: **vitest + tdd-цикл на `lib/*` и парсинге
расписания**; **sasha — при любой правке русских UI-строк и документации**;
**grill-me и humanizer-ru — инструменты «на большой случай»** (крупный план /
очистка генерированных текстов). Остальное — либо конфликтует с принятой
дизайн-системой, либо рассчитано на процессы (GitHub Issues, SaaS-мокапы,
командный harness), которых в проекте нет.

### Context7

### 21st.dev MCP

### Graphify

- **Источник:** [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify) (Apache-2.0/MIT)
- **Что делает:** строит по кодовой базе (tree-sitter AST, локально и без

  грепанья, `graphify path A B` — как связаны два понятия, `graphify explain`

- **Как стоит:** CLI установлен через `uv tool install graphifyy` (двойное

  Вызов: `/graphify .` в корне проекта.
- **Вердикт: ✅ установлен, попробовать.** Граф заменит «прочёсывание» файлов
  при вопросах вида «где считается пара активна»; особенно полезен, если
  вернётся задача рефакторинга. Первый запуск построит граф — посмотреть
  отчёт и решить, вписывать ли в AGENTS.md.

### Strix

- **Источник:** [usestrix/strix](https://github.com/usestrix/strix) (Apache-2.0)
- **Что делает:** автономный агент динамического пентеста: разведка,
  эксплуатация, подтверждение уязвимостей PoC-ами (OWASP Top 10), отчёты и
  автофиксы. Мульти-агентный, интегрируется с CI и MCP. Требует Docker и
  LLM API-ключ; песочница — Docker-образ.
- **Как ставится:** `pipx/uv tool install strix-agent` или
  `curl -sSL https://strix.ai/install | bash`.
- **Вердикт: ⏳ ждёт решения.** Применим только к собственным системам
  (shedule.rgsu.by — можно, чужое — нельзя). Для PWA с Google Sheets
  источником данных защита в основном на стороне фронт-валидации и прав
  доступа к таблице; реальная ценность — разовая проверка перед публичным
  деплоем. Установка отложена до явного запроса: тянет Docker-образ и ключ
  LLM.
