# AGENTS.md

Правила работы агента в этом репозитории. Читать в начале каждой сессии.

## Проект

Расписание занятий Филиала РГСУ в г. Минске. Next.js 16 (App Router), React 19,
TypeScript, Tailwind CSS v4, shadcn/ui, PWA (next-pwa + workbox), данные — Google
Sheets через `utils/loadSchedule.ts`.

## Доска задач

Проект ведётся на локальной доске `mcp-kanban` (проект `shedule`, порт 3010).
MCP-сервер уже подключён — инструменты доступны как `mcp-kanban.*`.

**Доска пассивная.** Перетаскивание карточки мышью никого не будит: агент
не читает доску сам и не запускается по событию доски. Карточка подхватывается
в начале сессии (см. ниже) или по команде человека.

### Статусы и что они означают

| Колонка | Смысл |
|---------|--------|
| `Backlog` | Идея, не согласована с человеком |
| `Todo` | Согласована, ждёт очереди |
| `In Progress` | **Агент работает прямо сейчас** |
| `Review` | **Требует решения человека** — не «сделано, посмотри», а конкретный вопрос/действие |
| `Done` | Сделано и проверено агентом (tsc + сборка + проверка в браузере) |

### Обязательный порядок работы

1. **Взял задачу → сразу `In Progress`.** До того, как начать что-то делать:
   `move_ticket` в `In Progress` (id колонки брать через `list_columns`).
   Никогда не выполнять задачу, не обозначив статус.
2. **Пиши, что делаешь, в описание карточки** (`update_ticket`, поле
   `description`): цель, подход, изменённые файлы. Это единственное место,
   где человек видит ход работы в реальном времени.
3. **Сделал и проверил → `Done`.** Проверка: `npx tsc --noEmit`, `npm run build`
   и (для UI) открыть страницу в браузере. Отдельного подтверждения человека
   не требуется — иначе `Review` превращается в свалку.
4. **В `Review` — только то, где нужен человек:** правка данных в таблице
   деканата, решение по архитектуре, деплой, коммит, неоднозначная формулировка
   задачи. Обязательно сформулируй в описании, **какое решение нужно**.
5. **Новая задача → сначала карточка** (`create_ticket`), потом работа.
   Карточка — это не отчёт постфактум, а план и трекер.
6. Подзадачи — через `create_subtask`, у крупных задач. Прогресс родителя
   виден по подзадачам. Выполненные подзадачи — сразу в `Done`.

### Начало сессии

1. `list_tickets` по проекту `shedule` — посмотреть, что в `In Progress`.
2. Если там есть карточка — взять её и продолжить (описание содержит, где
   остановились).
3. Если `In Progress` пусто — взять верхнюю карточку из `Todo` и сообщить, что
   берёшь её.

## Стиль интерфейса

Ориентир — Apple HIG. Конкретные правила (материалы, движение, цели касания,
типографика, тёмная тема, safe area) — в `docs/ui-guidelines.md`. Кратко:

- Материал «стекло» — композиция `backdrop-blur-[20px] backdrop-saturate-180`
  (рецепт Apple) + `bg-background/80` через `supports-[backdrop-filter]:`.
  Только для плавающих слоёв (шапка, панели). Обычные поверхности — плотные.
  Не собирать фильтр в один arbitrary-значение — получится вложенный blur.
- Движение: 0.2–0.35 с, кривая `cubic-bezier(0.22, 1, 0.36, 1)`, без отскока;
  `prefers-reduced-motion` обязателен.
- Движение в коде — только через `lib/motion.ts`: `motionTransition(reduce, {...})`
  и `MOTION_DURATION`. Свои `transition={{ duration }}` не писать.
  Кривая и длительность по умолчанию — в `@theme` (`app/globals.css`).
- Тактильная отдача — только через `lib/haptics.ts` (`haptic('light'|'success')`),
  не на каждое касание.
- Цели касания — не меньше 44×44 px на мобильном.
- Цвета — только токены. Шрифты: Evolventa (заголовки), Geist Mono (числа).
- Статусы — семантические токены `destructive` / `success` / `warning` / `info`,
  а не сырые `red-500` / `green-500`.
- Витрина компонентов и токенов — `/design` (тюнер темы, палитра, типографика,
  компоненты, иконки). Перед новым компонентом смотреть туда.

## Правила работы с кодом

- Перед сдачей: `npx tsc --noEmit` и `npm run build` — оба должны быть чистыми.
- Иконки — только из `@/components/icons` (Hugeicons). Новые иконки сначала
  ищутся в `node_modules/@hugeicons/core-free-icons/dist/esm/`, потом
  добавляются в `components/icons/index.tsx` **поштучным импортом** (иначе в
  бандл попадёт весь набор на 6000 иконок).
- `cn` импортируется из пакета `"cn"` (не из `@/lib/utils`).
- Токены Tailwind — только в `app/globals.css` (`@theme inline`). `tailwind.config.ts`
  удалён: конфигурации Tailwind v4 в проекте нет.
- Цвета: `bg-primary`, `text-muted-foreground` и т. п. Не хардкодить цвета.
- Стиль кода — как в соседних файлах: 4 пробела, double quotes, без `any`.
- Не оставлять за собой мусор: удалённые файлы — `git rm`, временные скрипты —
  вне репозитория.

## Чего делать нельзя

- Не деплоить без явной просьбы.
- Не менять `public/sw.js` вручную: он генерируется next-pwa на сборке.
- Не коммитить без просьбы (сейчас рабочее дерево содержит большой набор
  незакоммиченных изменений).
